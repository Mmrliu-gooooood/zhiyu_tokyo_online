## 1. 实施结论

在现有设置页、Settings Store、API 路由和媒体适配器上补齐自定义平台能力。用户能够在对应能力页面添加平台名称、API Base URL、协议类型、模型 ID，并自行填写 API Key；保存后可选择该平台用于实际生成或识别。

采用“**平台实例可自定义，接口协议由小型适配器负责**”的方案：平台名称和地址不写死；同一种协议可以供多个平台实例复用。保留现有文本、图像、视频、TTS、ASR 的模块分工，不建立统一的超级 Provider 框架。

本次不把需求理解为“任何 API 只填地址和 Key 就能工作”。不同平台可能采用不同鉴权、请求字段、返回格式和异步任务协议。首版覆盖 OpenAI 兼容协议以及 OpenRouter、硅基流动实际需要的协议；与这些协议一致的其他平台无需改代码即可手动添加。完全不同的私有协议，后续仍通过小型适配器扩展。

交付完整性要求：**设置页可添加、刷新后配置保留、真实调用使用用户选择、后台生成可读取同一配置**，四项缺一不可。

## 3. 架构边界与禁止事项

### 3.1 保留的结构

1. 配置仍放在现有 `providersConfig`、`imageProvidersConfig`、`videoProvidersConfig`、`ttsProvidersConfig`、`asrProvidersConfig` 中。
2. `generateImage()`、`generateVideo()`、`generateTTS()`、`transcribeAudio()` 继续作为各自领域的调用入口。
3. 内置 Provider ID、默认配置、已有厂商适配器和成功响应结构继续兼容。
4. 继续使用现有 PostgreSQL、Worker、任务重试、媒体落盘、日志和用量统计设施。
5. 浏览器原生 TTS/ASR 保持客户端专用语义，不伪装成后台 API 平台。

### 3.2 本次允许的必要扩展

- 图像、视频增加自定义 ID、配置字段和 Store 操作。
- 增加少量纯函数，负责内置目录与用户实例的合并、协议校验、URL 拼接。
- 媒体生成入口增加自定义协议分支，原有厂商分支继续原样工作。
- 增加一个服务器侧媒体配置解析模块，供 HTTP 路由、后台任务和 PRO 媒体工具共同使用。
- 后台任务增加媒体配置快照引用；这是将用户配置交给 Worker 的必要接口扩展，不改变调度架构。

### 3.3 不采用的做法

- 不一次性合并五类 Provider 的类型、Store 和目录。
- 不引入插件加载器、依赖注入容器、可执行脚本、请求映射 DSL 或通用工作流引擎。
- 不把用户平台注册进进程级 `IMAGE_PROVIDERS`/`VIDEO_PROVIDERS` 单例，避免多用户配置串用。
- 不用平台显示名称、域名包含关系或模型名称猜测协议。
- 不新增一组与 `/api/generate/*` 并行的自定义生成接口。
- 不复制完整厂商适配器来支持同协议的第二个域名。
- 不为了复用 UI，把所有能力表单改成复杂的动态表单系统。

判断边界：新增一个同协议平台应只产生配置数据；新增一种不同协议才需要增加适配器。

### 4.1 添加入口

沿用设置页左侧平台列表，在图像和视频列表底部增加“添加自定义平台”。TTS/ASR 沿用已有按钮和弹窗，补齐协议说明。文本模型保持现有入口。

表单顺序：平台名称 → 协议类型 → Base URL → 保存平台。进入配置面板后填写 API Key、模型和能力参数。允许无 Key 保存为“待配置”；不满足条件时不可作为正式任务的可用平台。

同一个服务商在不同能力中可以分别配置不同协议和 Key。首版不增加“全球平台账号”或跨能力自动同步 Key；用户需要共享地址时自行填写，避免引入凭据关联生命周期。

### 4.2 字段和状态

| 字段 | 行为 |
| --- | --- |
| 平台名称 | 必填，纯显示名称，不参与请求路由 |
| 协议类型 | 只展示当前能力可用的协议；每项附简短适用说明 |
| Base URL | 必填，包含版本前缀，例如 `/v1`；支持用户网关前缀；显示最终请求地址预览 |
| API Key | 密码框，沿用现有保存机制；不可进入错误提示和普通日志 |
| 需要 API Key | 默认开启；本地免鉴权服务可关闭，实际可访问性仍受部署策略控制 |
| 模型 ID | 正式调用必填，允许 `/`、`:`、`-` 等实际模型标识字符，不通过硬编码目录判断存在性 |
| 音色 ID | TTS 手动添加与选择，关联当前平台；不自动替换为 OpenAI 的音色 |
| 能力参数 | 沿用现有尺寸、比例、时长、格式、语速 UI；仅发送当前协议/模型支持的字段 |
| 状态 | 待配置、可选择、验证成功、验证失败、已停用；“可选择”不等于“已验证生成成功” |

平台支持重命名、修改、停用、删除。内置平台沿用现有管理规则。删除当前自定义图像/视频平台时清空相关选择并提示重新选择，不自动切换其他收费服务；音频保留既有浏览器回退语义，但明确提示，后台不会把浏览器音频当 API 使用。

首版以手动模型配置为必需路径；模型发现是辅助功能。发现接口缺失、被禁用或返回 404，不能阻止用户保存模型、发起实际测试。

## 5. 数据模型：只扩展现有配置

### 5.1 ID 与配置字段

- 图像拆分 `BuiltInImageProviderId` 与 `ImageProviderId`，后者增加 `custom-image-${string}`。
- 视频对应增加 `BuiltInVideoProviderId` 和 `custom-video-${string}`。
- 沿用 `custom-tts-*`、`custom-asr-*`、文本 `custom-*` 约定，使用随机 ID，显示名称变化不改 ID。
- 静态内置目录使用 `Record<BuiltIn...ProviderId, ...>`；动态用户配置映射允许自定义 ID，不用类型断言假定所有条目一定存在。
- 在现有媒体配置条目上补充 `isBuiltIn`、`customName`、`protocol`、`requiresApiKey`；继续使用已有 `apiKey`、`baseUrl`、`enabled`、`customModels`。
- 音频沿用已有 `customDefaultBaseUrl`、`customVoices`、`modelId`；只新增必要协议字段，不顺便统一历史字段命名。
- 自定义运行时配置显式携带协议与必需鉴权语义。协议使用各能力内部的有限联合类型，外部输入必须通过 Zod 校验。

默认不新增任意请求头、任意 JSON 参数或自定义路径编辑器。首版认证为 Bearer Key 或无鉴权；已有 Azure、豆包等特殊鉴权继续交给原适配器。将来有真实需求时再扩展对应协议，避免把 UI 变成 API 编程工具。

### 5.2 目录合并

在 `lib/media/` 增加轻量目录辅助模块，提供图像和视频的列举/单项解析函数：输入内置目录与当前用户配置，输出 UI 所需元数据。它不访问数据库、不发请求、不依赖 Zustand、不修改输入。

设置页和生成选择器使用相同函数，避免一处显示自定义平台、另一处仍只枚举内置平台。服务器读取已经校验的配置对象，不导入客户端 Store。

### 5.3 持久化迁移

当前版本为 4，实施时从实际最新版本递增一次：

1. 内置条目缺省 `protocol` 时继续沿用内置分支。
2. 旧自定义 TTS、ASR 分别补为 `openai-speech`、`openai-transcription`；保留 Key、地址、模型、音色、启用状态。
3. 图像、视频选择恢复时，同时认可内置目录和结构合法的当前用户自定义条目。
4. 内置目录刷新、服务器配置同步只更新其所属条目，不清空自定义平台或手动模型。
5. 缺字段/未知协议的条目保留为待修复或不可用，不默默改成另一个协议。迁移必须可重复执行且不重复创建平台。
6. KV 未成功加载时沿用现有拒绝覆盖保护，不能把空初始状态保存为正式配置。

本次不更换 account KV，也不新增第二份可编辑配置仓库。现有设置含用户 Key 的存储语义保持兼容；不宣称本次已完成全项目凭据存储改造。后台执行所需副本采用下述加密快照。

## 6. 协议范围与适配方式

下表中的协议名称为拟新增内部标识。官方文档核对时间为 2026-09-06；上线前仍须针对实际模型执行契约测试，不使用固定示例模型作为默认可用保证。

| 能力 | 首版协议 | 接入决定 |
| --- | --- | --- |
| 文本 | 已有 OpenAI/Anthropic/Google 等 | 继续现有逻辑，不重写 |
| 图像 | `openai-images` | 复用现有 Images 适配器的最小共同请求，明确自定义模型/地址必填 |
| 图像 | `siliconflow-images` | 小型新增适配器，处理 `image_size` 与 `images[]` 等差异 |
| 图像 | `openrouter-images` | 小型新增适配器，使用当前专用 Image API；输出转为现有媒体结果 |
| 视频 | `siliconflow-video` | 新增 submit/status 适配器，复用现有轮询设施 |
| 视频 | `openrouter-video` | 新增异步视频适配器，处理任务 ID、状态和鉴权内容下载 |
| TTS | `openai-speech` | 复用已有 `/audio/speech` 路径；补格式、可选参数和自定义平台校验 |
| ASR | `openai-transcription` | 复用或局部修正现有转录调用，保留上传格式和统一文本结果 |

以上协议均允许用户指定其他兼容平台的 Base URL，不校验厂商品牌或绑定官方域名。平台提供的协议与选项不匹配时给出明确错误，不偷偷改协议重试。

### 6.1 为什么不能只套用 OpenAI

硅基流动图片接口为 `/v1/images/generations`，但文档使用 `image_size`，结果为 `images[].url`；现有 OpenAI 适配器发送 `size` 并读取 `data[]`，因此直接换 Base URL 不足以兼容。[硅基流动图片 API](https://docs.siliconflow.cn/cn/api-reference/images/images-generations)

当前 OpenRouter 专用图片 API 使用 `POST /api/v1/images`，可返回 `data[].b64_json` 与 `media_type`。应使用明确协议处理路径和图片类型，不能仅凭“OpenAI 兼容”认定现有 `/images/generations` 可以直接工作。[OpenRouter Image Generation](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)

硅基流动视频通过 `/video/submit` 提交，并以 `requestId` 调用 `/video/status` 获取结果；OpenRouter 视频通过 `/videos` 提交、按任务 ID 查询，并使用内容下载接口。二者应分别适配，不设计含糊的“通用视频 API”。[硅基流动提交接口](https://api-docs.siliconflow.cn/docs/api/video-submit-post)、[硅基流动状态接口](https://docs.siliconflow.cn/cn/api-reference/videos/get_videos_status)、[OpenRouter Video Generation](https://openrouter.ai/docs/guides/overview/multimodal/video-generation)

两家平台的语音文档均提供独立语音接口，可以优先验证现有 OpenAI 兼容语音路径；具体模型、音色、参数支持仍要按平台校验。[硅基流动 TTS](https://docs.siliconflow.cn/cn/api-reference/audio/create-speech)、[硅基流动 ASR](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)、[OpenRouter TTS](https://openrouter.ai/docs/guides/overview/multimodal/tts)、[OpenRouter STT](https://openrouter.ai/docs/guides/overview/multimodal/stt)

### 6.2 适配器约束

- 自定义平台必须显式提供 Base URL、模型 ID；缺失时返回配置错误，不能回退到 OpenAI 官方地址或默认模型。
- Base URL 统一去掉末尾斜杠，与协议相对路径拼接；保留 `/api/v1` 等前缀，不重复补 `/v1`，不以开头 `/` 的相对 URL 意外覆盖前缀。
- 普通字段通过类型化映射发送。图像宽高、视频时长、音频格式不支持时，应报错或按已声明的模型能力规范化，不能伪造支持范围。
- 图像输出映射为现有结果。必要时只增添可选 MIME 信息，修正下游将所有 base64 默认当 PNG 的假设；首版不支持的 SVG 输出明确拒绝，不直接注入页面。
- TTS 使用用户填写的模型/音色；根据协议支持发送输出格式、语速，不依赖 OpenAI 默认音色。ASR 保留真实文件名/MIME 和音频字节，不把未经转换的数据重新标成 WAV。
- 不支持的参数不靠无限重试猜测。错误保留平台标识、协议、HTTP 状态、请求 ID，并脱敏。

### 6.3 视频轮询与媒体存储

复用 `lib/media/polled-task.ts`。若需取消，增加可选 `AbortSignal` 和恢复任务 ID 的小型接口扩展，保持已有调用兼容，不创建第二个轮询引擎。

提交后记录上游任务 ID，后续只查询；已知失败、超时和提交结果不明分开处理。Worker 重启后优先恢复已记录任务。上游未提供幂等保证且提交结果未知时，沿用现有未知提交处理，不自动再次提交收费任务，也不承诺跨平台严格 exactly-once。

OpenRouter 内容接口可能需要鉴权，因此适配器在服务器侧完成受控下载，再交给现有媒体落盘流程；如现有视频结果仅接受 URL，只增加可选字节/MIME 分支，保留原 URL 分支。不能把需要 Key 的 URL 或 Key 本身交给浏览器播放。

结果及时进入项目现有媒体存储；课程记录继续引用项目媒体地址，不能长期依赖供应商临时 URL。缓存命中必须包含用户、平台实例、模型和有效配置版本，不能跨账号复用私有请求结果。

## 7. 服务端与后台任务：必要的小范围打通

### 7.1 一个媒体配置解析边界

建议新增 `lib/server/media-provider-config.ts`，分别暴露类型化的 image/video/tts/asr 配置解析函数，不新增万能 `executeProvider()`。

解析顺序固定为：

1. 验证当前请求/任务的 owner，以及部署策略。
2. 管理员禁用优先；管理员已配置的内置平台继续使用其 Key、地址和模型约束。
3. 自定义实例必须解析当前 owner 提供并经过校验的完整配置；不能因 ID 有 `custom-` 前缀就直接视为可信。
4. 校验协议、地址、模型、音色、必需 Key 和启用状态，返回领域运行时配置。
5. 只有未显式选择平台的旧调用，才使用现有服务器默认逻辑；用户显式选择失败时，不回退到其他平台。

内置目录与用户配置分别处理，服务器策略函数保持现有职责，不把用户实例写入 `provider-config.ts` 的环境变量/YAML 缓存。

### 7.2 HTTP 路由契约

扩展现有 `/api/generate/image`、`/api/generate/video`、`/api/generate/tts`、`/api/transcription` 及图像/视频验证路由。旧调用方式继续兼容。

- 图像/视频 JSON 请求增加可选 `providerConfig` 对象，仅允许该能力的已知字段；旧内置请求继续使用原有头字段。
- TTS 沿用现有 JSON 配置；ASR 沿用 multipart，并为协议等补充明确字段，不迁移音频为 base64 JSON。
- 自定义完整配置存在时，平台 ID 必须与外层选择一致；冲突直接 400，不混合两个来源的 Key、地址和模型。
- 身份来自现有鉴权，不接受客户端自报 `ownerId`。预览和验证同样执行鉴权、地址校验、限流及配置解析。
- 正式任务只读取服务器已绑定配置，不能从生成模型输出、提示词或工具参数读取 Key/协议。

### 7.3 后台配置快照

仅把 Key 留在浏览器会导致 Worker 无法调用；把 Key 直接加入普通任务 JSON 会破坏现有不含秘密的任务契约。因此采用**任务专用加密快照**，不建立第二套可编辑平台管理系统。

建议实现一个 `media-config-snapshots.ts`，复用现有 PostgreSQL 连接池、owner 身份和事务设施。增加一张功能专用表，存储 `id`、`owner_id`、`schema_version`、`ciphertext`、`created_at`、`revoked_at`，以及撤销查询所需的非敏感平台实例 ID；内容不可原地修改，改变配置创建新快照。

快照内容仅包括本次选用的图像、视频、TTS 配置和实际引用的角色音色配置，不复制完整 Settings Store。ASR 当前是请求内识别，无需为了字段对称加入后台快照。

任务 JSON 与 PRO 会话只保存可选快照引用。创建任务/会话时先校验并封存，入队后 Worker 依据 owner 和引用读取。复用现有 PRO 加密算法与密钥配置的成熟方式；如抽取公共代码，只抽取加解密小函数，保留 `pro-model:v1` 的既有 AAD 和文本连接行为，媒体使用独立 AAD 命名空间。缺密钥时报明确配置错误，禁止降级明文。

不直接复用 `pro_model_connections` 的文本上下文或“最新连接”查询：它具有文本模型和连接版本语义，媒体任务快照没有理由改变该契约。一个功能专用快照表比重构为全局凭据框架更符合本次改动边界。

生命周期约定：

- 普通编辑不改变已绑定任务；新任务使用新快照。
- 停用/删除或清除 Key 时，撤销当前 owner 对应平台实例的快照，后续调用拒绝；已在上游执行的请求按现有取消能力处理。
- 管理员禁用策略每次执行仍检查，不会被旧快照绕过。
- 重试继续使用原引用，不重新读取最新设置；快照不可用则提示重新配置或重建任务。
- 清理仅针对已结束且超出现有任务保留期的、无活跃引用快照；不能固定短 TTL 导致长任务中途失效。
- 任务幂等判断使用非敏感配置意图指纹；服务端指纹需使用带密钥摘要，不公开含秘密配置的普通 hash。随机快照 ID 不应导致相同提交被判断为不同意图。

### 7.4 必须接通的消费端

1. `generation-jobs/contracts.ts`：增添可选引用，不放宽为任意 JSON，也不接收任务正文中的明文 Key。
2. `generation-jobs/preflight.ts`：校验用户快照中的媒体配置，保留原有文本/搜索等校验，不直接删除检查。
3. `generation-jobs/config-snapshot.ts`：区分服务器配置版本与用户快照，避免仅用全局服务器 hash 判断用户配置有效性。
4. Worker 组装入口：解析一次当前任务绑定，依赖注入现有媒体执行点；不得读取客户端 Store 或进程全局“当前用户”。
5. PRO 会话创建/恢复与 runner 组装：传递可选媒体引用，并通过现有媒体工具依赖注入接口提供配置。
6. `agent-runtime/generate-image.ts`、`generate-video.ts`：可用性判断和真实选择都使用同一解析结果，不再将自定义 ID 静态过滤掉。
7. `agent-runtime/scene-tts.ts`：使用会话配置及角色音色绑定，保持已有语音资产保存与播放契约。
8. 客户端媒体选择器、试听、录音识别、重新生成语音等入口：传递协议和用户配置，不能仅设置面板测试支持。

## 8. 地址、凭据与错误处理

自定义 Base URL 会使服务器请求用户提供的地址，本功能应延续并补齐已有防护，而非开放任意代理。

- 复用 `ssrf-guard.ts`、已有受限下载实现和模型请求校验方式；提交、查询、结果下载以及重定向目标都执行校验。
- URL 不允许用户名/密码、片段或把 Key 放入查询串。默认公网 HTTPS；本地 HTTP/私网访问遵循已有部署配置，不能因为选择自定义协议自动放开。
- 认证请求默认不自动跟随重定向。确需跳转时逐跳校验，不能将原平台 Key 转发给不同 origin；供应商 CDN 下载通常不携带原 Key。
- 对接入点的 DNS/连接校验复用现有工具；如果只有调用前 DNS 检查，补实际连接约束，不能把一次解析当作防止 DNS 重绑定的保证。
- 超时、响应字节上限、上传大小、并发限制沿用项目设施；新的协议分支必须覆盖。
- 缺 Key、缺模型、未知协议、禁用平台返回可操作的配置错误；401/403、404、429、超时、内容拒绝和响应不兼容分别呈现。
- 页面展示脱敏 Key；服务器日志、用量记录、课程 JSON、普通任务事件不得包含 Key、认证头、音频原文或完整敏感响应。

## 9. 验证设计

### 9.1 区分验证等级

“检查配置”只验证字段与可选的低成本发现接口。界面显示“配置完整”“鉴权检查通过”或“此协议不提供无生成验证”，不能将 `/models` 可访问显示为“生成成功”。

“实际测试”由用户主动点击，按钮说明可能产生费用。图像返回缩略图，视频返回任务进度及可播放结果，TTS 播放短音频，ASR 使用用户录制/上传的音频返回文本。测试和正式调用共用协议适配器，不为测试另写一套请求。

### 9.2 自动化验收矩阵

优先使用现有路由集成测试和模拟 HTTP 服务验证真实请求/响应，避免大量只镜像内部函数的测试。

| 场景 | 验收结果 |
| --- | --- |
| 添加两个名称相同、地址不同的自定义实例 | ID 独立，修改或删除一项不影响另一项 |
| 自定义图像/视频保存后重载、服务器同步 | 实例、Key、模型与选择保留，未回退内置平台 |
| 老自定义 TTS/ASR 数据迁移 | 原字段完整保留，协议按原行为补齐 |
| 不提供 `/models` 的平台 | 可手动配置，实际测试成功时仍可使用 |
| OpenAI 兼容图像返回 URL/base64 | 两种结果均被正确保存和展示 |
| 硅基流动图像 | 发出正确字段，读取 `images[]`，不错误套用 OpenAI 结果结构 |
| OpenRouter 图像非 PNG 位图 | MIME、扩展名、播放/导出读取正确；不支持格式明确失败 |
| 两种视频协议 | 提交一次、正确查询、处理成功/失败/超时；鉴权下载结果能播放 |
| 视频取消、Worker 重启、提交结果未知 | 停止无效轮询；已知任务不重复提交；未知提交不盲目重试 |
| TTS 用户模型/音色与 ASR multipart | 请求没有替换为 OpenAI 默认值，格式与内容一致 |
| 预览、普通生成、后台课程和 PRO 媒体工具 | 均使用用户指定实例、模型及配置，不选目录第一项 |
| 关闭页面后 Worker 执行 | owner 对应快照可读取并正常生成 |
| 运行中修改、撤销、删除 | 修改不漂移；撤销后的下一次调用被拒绝 |
| 两个用户使用同一服务商 | 快照、Key、缓存和任务引用均隔离；不能猜 ID 越权读取 |
| 管理员配置、禁用和旧无引用任务 | 原有优先级和兼容路径不变 |
| 私网、重定向、跨域下载、超大响应 | 按现有部署策略拦截；Key 不跨域泄露 |
| 第三方真实服务 401/404/429 或协议错误 | 输出明确脱敏错误，不静默切其他厂商 |

已有回归基础包括 `tests/settings/custom-provider-baseurl.test.ts`、`tests/store/settings-validation.test.ts`、`tests/store/settings-server-sync.test.ts`、`tests/media/`、`tests/audio/`、`tests/agent-runtime/` 相关用例，以及 `e2e/tests/settings-kv-persistence.spec.ts`、`e2e/tests/managed-provider-620.spec.ts`。

实施完成后运行受影响 Vitest 用例、TypeScript 检查、受影响文件 ESLint、国际化键检查及设置/实际调用的 Playwright 用例；涉及 `@openmaic/storage` 包契约时追加对应包测试。真实第三方测试使用用户配置的有效 Key，不把付费外网调用作为默认 CI 步骤。

本方案阶段仅检查代码与官方文档，没有用户 Key，未执行付费接口调用，也未声称上述集成测试已经通过。

## 11. 实施顺序与完成门槛

### 第一步：配置与图像纵向闭环

补图像/视频类型和迁移，落地图像添加 UI、动态目录、服务器解析以及 OpenAI 兼容图像协议。用模拟第三方地址完成“添加 → 填 Key/模型 → 保存 → 刷新 → 生成图像”的闭环，确认原内置用例不回归。

### 第二步：平台协议与语音补齐

实现硅基流动/OpenRouter 图像、视频协议，复用音频兼容路径并修正实际差异。完成模型手填、音色、格式、错误反馈和实际测试 UI。视频复用既有轮询、取消与媒体保存。

### 第三步：后台和 PRO 任务绑定

实现加密媒体快照、必要数据库迁移、任务/会话可选引用、预检及依赖注入。验收关闭页面后继续运行、重启恢复、修改不漂移、撤销与 owner 隔离。

这一步属于本需求必需工作，不能以“设置页已经能测通”为理由跳过。文本后台已有的独立限制保持原契约，不借此需求重写文本生成流程。

### 第四步：统一验收与发布

运行第 9 节回归，确认各入口使用同一配置；验证旧数据和管理员策略，补充用户操作说明，再发布完整功能。

可以按以上顺序拆分小提交，但正式宣布完成前必须全部通过。若分阶段部署未覆盖完整协议，界面只展示真实可用项，不能提前展示不能执行的选项。

回滚保持增量：先停用新建入口与相关新任务提交，等待或终止依赖新协议的在途任务，再回退应用版本；保留自定义数据和快照表，不执行删表/清配置。防止旧版本读取新持久化版本后以默认设置覆盖用户数据；必要时保留只读兼容保护再回退。

## 12. 不在本次范围

- 任意 API 的零代码请求/响应映射、脚本插件、上传自定义适配器。
- 所有厂商的所有模型、实时双向语音、声音克隆、图生视频和多图编辑等全能力覆盖；已有功能保持不回归，新增能力另行立项。
- 平台商店、自动注册账号、跨平台价格选择、自动切换收费平台。
- 全局平台账号/凭据中心、全部历史 Key 存储迁移、统一五类 Provider 大重构。
- 替换 Worker、重做任务调度、重写 PRO 文本模型连接和持久化体系。

本方案的扩展终点是：保留现有分层，增加可配置平台实例、有限协议适配和任务配置传递。未来新增兼容平台通过用户配置完成，新增协议则局部增加适配器，避免业务页面和任务编排持续堆积厂商判断。
