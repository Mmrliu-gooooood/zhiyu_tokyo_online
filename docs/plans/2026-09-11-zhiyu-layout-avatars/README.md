### 3.1 实施顺序

1. 对照固定版本 diff 和当前本地组件，手工移植与布局有关的 hunk。不要执行整仓库 `git pull`、merge 或直接覆盖整个文件；不以 cherry-pick 作为默认方案。
2. 在现有组件增加 `sectionRef`、`compact` 状态与 `ResizeObserver`，观察实际 section 的 `clientHeight`。首次挂载测量一次，卸载时断开 observer。
3. 使用 PR 的 760/820px 作为初始阈值，明确等号行为：

   ```ts
   setCompact((previous) => (previous ? height < 820 : height < 760));
   ```

   普通模式高度小于 760 时进入紧凑；紧凑模式到达 820 时恢复普通；中间区间保持前一模式。不要依据紧凑后的内容高度来回判定，以免反复切换。
4. 构造三层结构：

   ```text
   section：absolute inset-0 z-[105] overflow-hidden
   ├─ 原有背景、光晕、彩纸（固定装饰层）
   └─ 正文滚动层：absolute inset-0 overflow-y-auto overflow-x-hidden
      └─ 撑高包装层：min-h-full flex items-center justify-center
         └─ 正文：按 compact 调整尺寸和间距
   ```

   关键是包装层能随正文增高，不能再把高度受限的滚动容器本身当作垂直居中的 flex 容器。
5. 保留现有状态公告、统计计算、动画逻辑和 reduced-motion 支持。仅让 `QuizRing` 接收可选 `compact`，改变显示大小，不改 SVG 的计算坐标与成绩。
