# P3-2 教学图片细节质量（等分、数量、标注与公式）

- **环境/日期/代码版本/镜像：** 2026-09-26（UTC+8）。东京生产服务器 `154.36.184.44`，东京 Supabase `lvbtgwlsebzbtcvjwktq`。图片模型为平台默认 `minimax-image / image-01`（`lib/server/platform-default-models.ts`），文本模型为 `ZHIYU 默认模型 / DeepSeek V4.1 Flash`。基线图片在服务器上用发布镜像 `zhiyu-supabase-worker:release-20260926` 的 Node 运行，修改后课程由 `release-20260926b` 生成。费用上限（用户授权）：¥50。
- **初始问题及复现步骤：** 方案第 11 节：分数课图片“四等分”视觉不严格。代码追踪：大纲生成（`requirements-to-outlines` + `snippets/image-instructions.md`）由 LLM 写出 `mediaGenerations[].prompt`，`lib/server/generation-pipeline/media.ts` 把 prompt **原样**连同 `aspectRatio`（默认 16:9）交给图片模型，没有任何约束被丢失或改写——问题不在“要求丢失”，而在于把依赖精确几何/计数的图交给了图像模型。原模板还明确建议“diagrams, charts”用生成图片。
- **正确性判定标准（用户授权执行者制定）：** 每张图对照其规格逐项判定，全部适用项满足才算“通过”；看不清或有歧义记为“需人工复核”，不计通过。
  1. **数量**：要求的部分数、物体数、刻度数、柱数完全相等。
  2. **等分**：各部分形状一致，面积/长度肉眼相等（相对偏差 ≤ 10%）。
  3. **涂色/标记**：涂色份数、箭头或指针位置与规格一致。
  4. **标注与公式**：规定的数字、分数、算式全部出现且正确；不出现错误、乱码或与规格矛盾的文字。
  5. **无干扰**：没有多余的可数对象或会误导学生的元素。
- **固定样本集（10 项，中文小学数学）：** S1 圆四等分涂 1 份标 1/4；S2 分数条五等分涂 3 份标 3/5；S3 两条五等分分数条演示 1/5+2/5=3/5；S4 0–1 数轴八等分标 3/8；S5 一行 7 个苹果；S6 3×4 点阵标 3×4=12；S7 正方形 2×2 涂 2 格标 2/4=1/2；S8 披萨六等分拿走 1 块；S9 钟面 3:30；S10 柱状图 周一 2 / 周二 5 / 周三 3。prompt 按大纲生成器的写法（中文描述 + 白底教学插图），全文保存在 `baseline-manifest.json`（本地工作目录，未入库）。

## 修改：精确图改由原生幻灯片元素绘制

按方案第 3 步“评估现有 SVG/画布或结构化插图路径”：幻灯片已支持任意 SVG 路径的 `ShapeElement`（含 `outline` 边框）、`LineElement`、`LatexElement` 与 `ChartElement`（含 bar/pie），能精确表达上述图形，无需新增产品交互或数据迁移。只改两处提示模板：

1. `packages/@openmaic/generation/snippets/image-instructions.md`（大纲阶段，开启图片生成时注入）：不再建议用生成图片画 diagrams/charts；明确列出分数与等分、需要数的数量、数轴/刻度/钟面、带具体数值的图表、带给定长度或角度的几何图、任何必须正确的标注或公式——这些**不得**添加 `mediaGenerations`，改为在该页 `description`/`keyPoints` 中写清图形规格；必须用图片表现可数物体时写明“exactly N”，不让图片模型写公式或数字标注。
2. `packages/@openmaic/generation/templates/slide-content/system.md`（逐页生成阶段，总是注入）：新增“Precise Teaching Diagrams”配方——每个部分是独立 `ShapeElement`（便于计数），统一边框；分数条 n 个等宽矩形无缝并排；圆/披萨 n 等分给出 n=2/3/4/5/6/8 的扇形边界点（由脚本按 −90° 起顺时针计算、保留 4 位小数）与路径写法；2×2 网格、数轴（1 条轴线 + n+1 条刻度 + 标签）、点阵的画法；数据用 `ChartElement`、分数与算式用 `LatexElement`；输出前核对形状数、涂色数与标注。

自然插图（场景、人物、风景等）仍走图片模型，未关闭任何生成模式。
