# Pro 提问与工作坊计划修复验证

日期：2026-09-13。已修改代码并重新构建、替换 Web 与 Worker 容器。

## 最小修改方案

本次涉及 5 个业务文件、3 个测试文件。普通模式课程生成流程、共享模型流适配器、其他页面和样式未修改。

- `ask_user` 在既有 `prepareArguments` 钩子中兼容一层 JSON 字符串根参数，发生在 schema 校验之前。只接受解析后的非空对象；数组、损坏 JSON 和错误字段继续由原校验器拒绝。避免让模型因可以确定性修复的编码问题重试。
- 工作坊技能说明原先将 interactive 与 quiz 合并描述，与实际校验不一致。说明现已明确：interactive 至少 `max(3, ceil(总页数 × 0.4))`，另有至少 2 页 quiz；quiz 不计入 interactive。
- 提交工具说明要求先分配页面类型，再写内容，并按最终 outlines 数组复算。既有校验失败信息增加实际页数、所需整数页数和当前缺口，避免修改总页数后反复差一点达标。校验阈值与接受条件不变，也没有直接改标签冒充互动内容。
- 唯一 UI 修改为 Pro 的 `submit_course_generation` 工具行：使用既有中文翻译显示“规划课堂”和约束问题数量。原始诊断仍可展开查看；历史失败记录仍保留。

选择上述方案，未增加自动重试服务、新规划工具或普通模式处理分支。它直接处理参数编码和说明/校验不一致，改动范围较小。模型仍可能生成不合规计划，因此保留校验；不承诺以后绝无计划重试。

## 后续生成中断的根因与修复

用户手动重试后，同一任务到达 `run_no=4`，仍只有 3/8 页，最后报 `GENERATION_STEP_NOT_RUNNABLE`。用户另告知已充值 MiniMax；以下两个失败均在不调用付费 API 的本地回归中得到复现，不能归因于余额不足。

1. 模型计划中的 `widgetOutline.keyVariables` 是字符串，simulation 生成器直接 `.join()`，产生 `TypeError: widgetOutline.keyVariables?.join is not a function`。因此第 6 页在发出内容模型请求之前就失败，并使并发请求被记为结果未知。修复在原提示构建位置兼容字符串与数组，保留文本含义，同时支持已持久化的失败课程恢复。
2. 其他并发步骤在失败收尾时会回到 `pending`，但仍累计了执行次数；手动 retry 原先只为 failed/uncertain/retry_wait/running 恢复次数，不包括这些 pending 步骤。连续失败后它们达到 3 次上限，再次手动重试也不能运行。修复将 pending 纳入手动重试额度恢复，成功步骤仍保持不可变。
