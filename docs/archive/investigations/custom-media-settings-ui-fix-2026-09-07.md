# 图像、视频自定义平台入口修复

## 问题与原因

用户截图中图像、视频设置页没有添加平台按钮，标题显示 `settings.undefined`。

当前工作区已经具备自定义媒体协议、Store 操作、动态目录以及后台配置传递。遗漏集中在前端：设置页仍直接枚举 `IMAGE_PROVIDERS`/`VIDEO_PROVIDERS`，没有给已有平台列表组件传入添加回调；详情和生成菜单也未消费动态目录。

另一个独立的显示问题是：尚未选择生成平台时，详情标题对空 ID 拼接了翻译键。i18n 返回的 `settings.undefined` 是非空字符串，原来的 `|| provider.name` 无法兜底。

## 本次修改

- 图像、视频平台列表底部加入“添加自定义平台”，复用已有平台目录和 Store 操作。
- 添加弹窗支持平台名称、协议、Base URL、是否需要 API Key；保存后进入新平台详情，填写 Key 和自定义模型。
- 图像协议支持 OpenAI Images、SiliconFlow Images、OpenRouter Images；视频协议支持 SiliconFlow Video、OpenRouter Video。兼容这些协议的其他 API 平台可使用自己的地址。
- 详情页支持自定义名称、协议、启停、删除和模型编辑；自定义模型只显示一次。
- 自定义平台的“检查配置”将完整协议配置传给已有验证路由，并明确说明没有执行实际生成、没有验证 Key/模型可用性，避免误报“连接成功”。
- 生成菜单列举已配置的自定义平台，沿用既有可用性判断；禁用或缺少地址的自定义平台不会进入可用列表。
- 输入地址暂时清空时保留平台编辑面板，不因目录过滤而突然跳转。
- 空生成选择只在设置面板使用可显示的内置平台兜底，不擅自修改实际生成选择；标题不再拼接未定义翻译键。
- 新增文案覆盖现有 12 个语言文件。

本次没有重写协议适配器、API 路由、数据库、任务调度或 PRO 模型架构。

- 两项完整流程覆盖添加、填写模型和测试凭据、配置验证请求、地址编辑、刷新持久化、生成菜单选择、删除。
- 相关 Vitest 共 157 项通过：初次 155 项回归，补充两个地址清空场景后目录测试 8 项通过。
- `tsconfig.build.json` 类型检查通过。
- 本次 TypeScript/TSX 业务文件 ESLint 无错误；项目 ESLint 默认忽略 e2e 文件，e2e 已由 Playwright 执行。
- i18n 键对齐检查通过，修改文件差异检查通过。

本地开发首页存在另外的客户端加载错误：生成包的服务器提示词加载模块进入浏览器，触发 `fileURLToPath is not a function`。为隔离该问题，以上浏览器测试通过临时页面直接加载正式 `SettingsDialog` 和 `MediaPopover`，没有替换这两个组件；临时页面已移出 `app/`，不会进入生产构建。测试文件保留默认首页入口，支持 `SETTINGS_TEST_PATH` 指定隔离宿主。
